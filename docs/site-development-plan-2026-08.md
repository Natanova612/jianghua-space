## 二、双语架构方案（单站点 + 页内切换）

**方案**：不做中英文两个镜像站，只做一个网站、一套 URL。每个文案块同时渲染中英文两份，用 `data-lang` 标记，全局切换按钮控制显隐。

### 核心机制

1. **`Lang.astro` 组件**：包裹双语文本
   ```astro
   <Lang zh="独立经营顾问" en="Independent Business Consultant" />
   <!-- 渲染为 -->
   <span data-lang="zh">独立经营顾问</span>
   <span data-lang="en" class="hidden">Independent Business Consultant</span>
   ```
2. **`LanguageSwitcher.astro`**：导航右侧 `中 / EN` 切换；选择存入 localStorage，刷新后保持
3. **全局脚本**（约 20 行，放 BaseLayout）：读取 localStorage → 切换所有 `[data-lang]` 元素显隐 → 设置 `<html lang="zh-CN|en">`

### 双语覆盖范围

| 页面类型 | 双语策略 |
|---------|---------|
| 结构性页面（首页/服务/关于/简历/联系/案例） | 全文双语（Lang 组件逐段包裹） |
| 长文（/notes 文章） | 中文全文 + 英文摘要（摘要可切换），不强制全译 |
| 对外汉语页（隐藏筹备） | 全文双语（受众即英文用户） |
| 旧存档页（/starfield 等） | 仅中文，不翻译 |

### SEO

- 单一 URL，中英文内容同页存在，搜索引擎均可抓取
- `<html lang>` 随用户选择动态切换（初始默认 zh-CN）
- 隐藏页（对外汉语）加 `<meta name="robots" content="noindex">`，不进导航与 sitemap

### 优势

- 无需 `/en/` 目录与双套路由，工作量比镜像站方案省约 40%
- 链接唯一，分享和 SEO 都简单
- 文案集中在 Lang 组件处，维护成本低于两套页面

## 三、视觉方向

### 设计概念：「纸 · 墨 · 印」

在现有 Human 暖白基调上做记忆点强化，不商务、有东方感、有手作温度：

| 元素 | 现状 | 调整为 |
|------|------|--------|
| 底色 | 暖白 | 保留，微调为更纸感的米白 `#f7f3ec` |
| 主文字 | 深灰 | 墨色 `#1f2328` |
| 记忆色 | 无 | **朱砂印红 `#c8391f`**（仅用于印章、关键强调、CTA） |
| 辅助色 | aurora-green | 黛蓝 `#2f4a5e`（链接、次级强调） |
| 印章元素 | 无 | **个人名章**：设计一个“姜华”或“华”字方形印章（SVG/图片），作为全站标志，出现在导航、首页、页脚 |

### 首页创意：「名片 + 卷轴」

首屏不做常规 hero，做成一张**竖版名片**概念：

1. **首屏（名片）**：
   - 左侧/中央：超大“姜华”二字 + 朱砂印章
   - 定位语逐行呈现（打字机或淡入）：独立经营顾问 → 15 年互联网产品及用户运营 → 咨询与运营陪跑
   - 底部一句英文小字（双语感的暗示）+ 语言切换
   - 两个 CTA：「看看我能做什么」（朱砂实心）/「联系我」（描边）
2. **第二屏（三扇门）**：三个服务入口做成三扇“门/窗格”卡片——经营顾问（大）、个人教练、对外汉语（标注“筹备中”灰显或不显示）
3. **第三屏（信任带 + 精选案例）**：横向卡片卷轴感
4. **第四屏（最新思考）**：2-3 篇文章卡片
5. **页脚**：印章 + 联系方式

实现成本：纯 Astro + Tailwind + CSS 动画，无重库。

## 六、技术注意事项

1. 保持 Astro 5 + Tailwind 3 现有栈，不引新框架
2. 双语统一走 `Lang.astro` 组件，禁止页面内硬编码双份文本；导航/页脚/按钮全部双语
3. 移动端优先检查首屏名片布局（大字 + 印章在小屏的缩放）
4. 旧页面（/starfield、/businessidea、/wetland-museum）不动逻辑，仅导航层面处理，保持仅中文
5. 每完成一个 P 阶段，本地 `npm run build` 验证后提交 git；推送仍走 WSL

## 七、战略补充（2026-08-11 用户讨论）

**双定位**：站点同时服务 Plan A（独立顾问获客）与 Plan B（重返职场面试）——「明 A 暗 B，各自成链」。门面是 A；B 的链路 = 定向简历 → 案例详情 → 作品直达。

**已定方向调整**：
1. **JD 匹配器**（Plan B 亮点，vibecoding 产品功能）：面试官粘贴 JD → `/api/match`（Vercel Serverless + Moonshot API）→ 坦诚匹配报告。事实源 = `src/data/profile.json`（能力底稿，含诚实 gaps）。待办：用户申请 MOONSHOT_API_KEY 并配置（本地 .env / Vercel 环境变量）
2. **简历不做多版本**：定向优化由 JD 匹配器承担；简历保持一份主版
3. **案例脱敏方案**：不用内部截图——自绘示意图（SVG）+ 数据区间化/相对化 + STAR 结构化文字复盘；自有作品（本站、湿地博物馆、AI 店长）全开放排最前
4. **内容引擎**：按「文旅平话」范式执行，见 `docs/content-playbook.md`；优先写「运营与营销反思」「从业者出路」两类
5. **Plan B 目标方向**：AI 产品和用户运营、文旅产业链 两个大方向
