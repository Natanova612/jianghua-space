# PRD：「透过AI看姜华」—— 站点交互核心（v2.0 定稿）

> 状态：**已定稿，待动工**
> 日期：2026-08-14（v2.0 定稿；v0.1 草案 2026-08-12）
> 背景：站点从「陈列式门面」升级为「交互式产品」。JD 匹配器已验证可行性（5 份真实 JD 测试，评分梯度 90/68/52/48/10，判断质量达标），现将其能力吸收进站点主体对话模块，匹配器本身下线。

## 一、产品定位

**一句话**：站点即产品，产品即证明——访客通过与「了解姜华背景信息的 AI 智能体」对话，完成岗位匹配、合作评估、了解其人其作。

**双层站点架构**：
- **核心层（交互）**：「透过AI看姜华」对话 —— 站点的心脏
- **栏目层（陈列）**：案例志 /work、思考集 /notes、其人 /about、简历 /resume —— 高级杂志式编排

**两个定位的承载**：
- Plan A（客户/合伙人）：合作可能性分析 + 案例 + 文章
- Plan B（面试官）：岗位匹配 + 简历 + 案例证据链

**隐藏线（不对外）**：
- 一个不对外的关于姜华的原始知识库，姜华持续补充个人信息，作为智能体语料
- 通过持续的 harness 工程训练智能体，使其回答更惊艳且可靠，最终成为一个可主动发起工作链接的助理
- **核心理念**：隐藏线到明线之间不是直接接通，而是隔着一层层精心设计的 agent skill——知识库如何沉淀、不同类型问题遵循什么回答原则，每一个都是独立的 harness 工程。没有这个打磨过程，产品就是毛坯 AI 问答，专业 HR 和合作伙伴一眼看穿，反而露怯。

## 二、用户与场景

| 角色 | 进来干什么 | 核心路径 | 目标动作 |
|------|-----------|---------|---------|
| 面试官/HR | 验证这人是否匹配岗位 | 首页 → 选「我是面试官」→ 粘 JD → 结构化报告 → 追问细节 | 发邮件约面 |
| 潜在客户（文旅企业主等） | 这人能不能帮到我 | 首页 → 选「我有合作」→ 描述业务 → 获得合作形式建议 | 发邮件/加即刻 |
| 潜在合伙人 | 看看是不是同路人 | 首页 → 随便聊聊 → 了解经历与思考 | 深聊 |
| 普通访客 | 被画卷吸引逛进来 | 浏览 → 好奇发问 → 留下印象 | 关注/传播 |

## 三、首页结构与视觉架构

三层背景保留（画/字/人）。「人」层的核心从静态文字变为对话入口：

```
卷首
├─ 姜华 + 名章（保留）
├─ 站点介绍（代替原来的三行定位：介绍该站点是姜华通过 vibe coding 建设，
│   基于自己的经历背景和近期实践构建了 AI agent，希望通过 AI agent 进行
│   更好的信息匹配和社交链接；给出几种建议的使用方式）
│   ※ 初版由 AI 起草占位文案，姜华后续替换为亲笔文案
└─ 【对话区】（新增，替代一切 CTA）
    ├─ 引导语：「山水已阅，不如开口。」（已定）
    ├─ 输入框（单行，回车发送）
    ├─ 三个意图签：我是面试官 ｜ 我有合作或项目 ｜ 随便聊聊
    └─ 对话展开区（首条发送后原位展开，流式逐字呈现）
```

**视觉架构原则（v2.0 升级）**：
- 对话区是卷首的视觉焦点，**输入框必须有足够的尺寸、对比度和存在感，不能被画卷淹没而被忽略**——它是一次视觉架构升级，不是往现有页面里塞一个组件
- 整体目标：让用户感受到进入一个姜华设计的虚拟空间，通过背景、色调、视觉设计感受到基本审美和内涵，同时通过使用指南和对话框快速明白操作动线。兼具科技感染力与人文内涵
- 网页的视觉和编排便此机会整体打磨一轮，更精准、更有深度
- 回答中涉及作品/简历时，AI 主动给链接（站内导流回栏目层），且必须设计好**回到对话的衔接**：对话状态保存在 sessionStorage，从栏目页返回后对话上下文仍在；栏目页提供回到对话的明确路径
- 移动端：对话区全宽，键盘弹出体验优先

**科技感方案：「活卷」（M1 一次做全，四层）**

核心思路：科技感不是给国风加一层科技皮肤（霓虹、玻璃拟态与纸墨互斥，不做），而是**让这卷纸活过来**——画在动、字在漂、章会盖、墨会显影，对话是它的呼吸。

- **L1 对话区即科技载体**
  - 流式显影：回复逐字出现复用「朱批显影」动效语言，字如墨迹洇开，非硬蹦
  - 输入框：宣纸质感容器 + 朱砂色呼吸光标细线（2s 明灭），加大尺寸与留白，成为卷首视觉焦点
- **L2 系统状态行**：对话区顶部一行 mono 小字（JetBrains Mono），如「分身在线 · 已读 212 本书 · 2,621 条划线 · 今日已答 N 问」——手写体与等宽体对撞即科技感，全部真实数据，科技感同时是信任感
- **L3 机关感**：三个意图签做成三枚小令牌/闲章（选中时钤印下压微动效，复用名章盖印动画体系）；精选对话卡片做成「卷宗」：编号（档 001）、时间戳、意图标签，mono 排印——精密感来自编号与秩序，不来自发光
- **L4 候墨：loading 即内容窗口（联动核心，替代原"变速联动"方案）**
  - 问题：k2.6 首字延迟 30-60s，干等是体验黑洞；反过来，这是访客注意力最集中的 30 秒
  - **对话框内**：固定的 loading 骨架（状态行「分身正在作答」+ 不定态墨线进度条，明确这是加载态）+ 下方轮换的「候墨碎片」卡片（每 8-12s 淡入换一条）：一条读书划线/批注、一个经历事实、一句工作方法、一段 AI 协作花絮。卡片带角标小字「候墨 · 等待时翻看一页」，视觉上从属于对话（更小字号、60% 透明度、无气泡样式），**绝不与正式回答混淆，不喧宾夺主**
  - **画卷字层联动**：发送后，ReadingDrift 飘动字层从日常「读书划线」切换为「候墨集」（姜华的工作笔记片段、思考短句），卷缘出现一枚「候墨中」小章；回答抵达后字层恢复日常集、小章收起——**访客一发问，整卷飘的字换了内容，空间在为他翻检档案**，这就是可感知的联动
  - 时序编排：0-2s 问题落卷显影（「分身已接卷」）→ 2s 起 loading 骨架 + 候墨碎片轮换 + 字层切换 → 首字抵达时墨线收笔、碎片隐去、回复显影 → 超 60s 未响应走降级文案
  - 移动端：字层本就弱化，候墨体验由对话框内碎片卡片承担
  - 碎片内容源：知识库新增 `waiting_cards` 集合（全部「公开」密级，见 6.1）

**导航衔接（站点级设计，非临时串联）**：
- 全站导航随本次改版重新设计，核心层与栏目层的关系在导航层面表达清楚，而不是靠子模块和小链接之间临时串联
- /resume 的 JD 匹配器模块**直接下线**，其入口位置改为导航级引导，指向首页对话（自动携带「我是面试官」意图）
- 匹配器的评分逻辑、证据锚定等 prompt 经验沉淀进对话版的面试官意图框架，不保留两个入口

## 四、对话核心功能规格

### 4.1 三意图
- **我是面试官**：引导粘 JD → 结构化输出（匹配度/匹配点附证据/差距风险/建议）→ 可多轮追问（"他 SQL 到底什么水平？"）
- **我有合作或项目**：先问诊（业务、卡点、目标）→ 给合作可能性判断（能帮什么、不适合什么、建议形式）→ 不适合的直说并给替代建议
- **随便聊聊**：开放问答，边界内知无不言
- 对话默认保留记录，姜华作为管理员可以进行记录的管理（置顶/删除，见 6.2 分步实现）

### 4.2 技术规格
- 接口：`POST /api/chat`，流式（Moonshot SSE → 纯文本增量直出）
- 模型：kimi-k2.6（temperature 固定 1，平台限制）
- 记忆：会话级（sessionStorage 保留会话，刷新可恢复；不做持久账号体系）
- 限流：10 次/分钟/IP；单次输入 ≤4000 字
- 降级：接口挂 → 显示「分身暂时离线，邮件可直接找到本人」+ 邮箱

### 4.3 护栏（安全红线，六条）
1. 话题边界：只谈职业相关；政治/隐私/无关请求礼貌引回
2. 事实边界：知识库是唯一事实源，禁止编造经历数据
3. 注入防护：拒绝"忽略指令/扮演他人"类请求
4. 隐私红线：家庭、收入、健康等不答，引导邮件问本人
5. 人设边界：明确自己是"AI 助理"，第三人称谈姜华，不冒充本人
6. **语料边界**：私有知识库内容按密级使用（见 5.1 分级），标注为「内化」的语料只能用于理解和表达，不得逐字引用或复述给访客

## 五、Agent Harness 工程（核心差异化）

这是「透过AI看姜华」与毛坯 AI 问答的分水岭。每个 harness 都是独立设计、独立验证的工程，逐个建设、持续迭代：

### 5.1 知识库沉淀 skill
- 原始语料（姜华持续补充的个人信息、经历细节、思考碎片）→ 结构化条目 → 姜华审核 → 入库
- **密级三分**：
  - `公开`：可直接引用（案例数据、公开经历）
  - `内化`：只用于理解和表达，不得逐字外吐（个人思考、未公开项目细节）
  - `绝不外泄`：仅用于校准事实底线，任何回答不得触及（家庭、健康、财务）
- 语料更新 = 更新文件 + prompt 调优 + 重新部署（RAG 思路，不做 fine-tune，成本最低、迭代最快）

### 5.2 分意图回答框架
- **面试官框架**：证据锚定（每个匹配点必须挂真实经历证据）、敢直说缺口（不硬凑）、评分克制有区分度——继承旧匹配器的验证经验
- **合作框架**：先问诊后判断、不适合的直说并给替代建议、不夸下海口
- **闲聊框架**：边界内知无不言，允许个性表达（见 6.3 人格）

### 5.3 质量巡检 harness
- 每周抽样对话日志，按「事实准确 / 边界守住 / 表达质量 / 导流恰当」四维评分
- bad case 回收进对应 harness 的规则或语料，形成迭代闭环

### 5.4 验收标准
- 灰度期内用 5-10 个新问题场景实测（含至少 1 个注入攻击、1 个隐私诱导、1 个跨意图混合问题），全部达标才算 M1 完成
- 达标的主观标准：**专业 HR 或潜在合作伙伴看完回答，感受到的是"这人被打磨过"，而不是"这是个套壳 chatbot"**

## 六、内容安排

### 6.1 能力底稿扩容（知识库 v1）
现状：技能/经历/gaps。需补：
- `faq_knowledge`：高频问题的标准答案（收费吗？怎么合作？base 哪里？时间投入？）
- `cases_digest`：每个案例的 3-5 句精华 + 链接（供对话引用导流）
- `voice`：语气样本（姜华自己的文字 + 微信读书划线/批注，让分身说话更像"他的人"）
- `waiting_cards`：候墨碎片（划线/经历事实/方法金句/AI 协作花絮，10-15 条起，全部「公开」密级，供 loading 轮换与候墨字层，见 L4）

### 6.2 精选对话记录（分步实现）
- **第一步（M1，静态）**：从内部灰度测试的 JD 记录和效果中精选若干条，脱敏后作为「历史精选对话」静态呈现，**位置在首页对话区下方**——让未发问的访客也能直观看到对话质量，内容显得丰满
- **第二步（M3，动态）**：接入存储与管理员鉴权，支持姜华后台对真实访客对话进行置顶/删除，静态精选逐步替换为真实运营内容

### 6.3 人格设定（已定）
- 更有个性的表达，允许偶尔引用姜华划过线的书里的句子
- 约束：引用必须真实（来自 voice 语料），频次克制（不每轮都引用），场景恰当（闲聊优先，面试官场景以专业为先）

### 6.4 栏目层（杂志化，后续阶段）
- /work 案例志：自有作品全开放 + 职场案例脱敏复盘（自绘示意图）
- /notes 思考集：文旅平话范式（content-playbook.md 已定）
- 栏目页被对话引用 → 形成「对话激发阅读，阅读激发对话」的循环

## 七、运营细节（已拍板）

1. **对话日志**：存。仅问题文本 + 意图类型，脱 IP；界面注明「对话内容可能用于改进服务」
2. **灰度策略**：BETA 标直接上首页；发布前内部灰度测试 5-10 个新问题场景，全部达标后正式对外
3. **卷首引导语**：「山水已阅，不如开口。」
4. **成本控制**：k2.6 按 token 计费；限流 10 次/分/IP 兜底；Vercel 侧设月度用量告警
5. **英文访客**：分身自动随访客语言切换，无需额外设计

## 八、风险

| 风险 | 缓解 |
|------|------|
| 模型延迟 40-60s 体验差 | 「候墨」机制把等待转为内容窗口（loading 骨架 + 碎片轮换 + 字层联动）；后续关注更快的模型 |
| 分身说错话/被注入 | 护栏六条 + harness 约束 + 日志巡检 + 一键下线开关（环境变量） |
| 私有语料外泄 | 语料密级三分 + 护栏第 6 条 + 灰度期专项测试 |
| API 费用失控 | 限流 + 月度用量告警 |
| Vercel 免费版函数超时 | 流式响应首字节快，超时风险低；持续观察 |
| 上线前 | 需在 Vercel 环境变量配置 `MOONSHOT_API_KEY` |
